4.0.0
    Version aligned with the Detect It Easy source (die_source 4.0.0), so
    `cdie --version` reports the same number as `diec`.

    Initial release.

    * Added die-update, the signature database updater: "die-update" installs
      a newer database, "--check" only reports (exit codes 0 current/installed,
      1 available, 2 network, 3 folder, 4 parameter, 5 verification,
      6 cancelled, 7 busy). Reads Detect It Easy's die.ini or native NTInfo/die
      settings; the default source is the current-database release (db.zip +
      db.zip.md5). Downloads are verified by size, MD5 and per-member CRC,
      the new database is loaded once, then swapped in by rename with
      rollback under a lock. db/die-update.ini records what was installed.
      Only db/ is installed from db.zip; other folders in it (db_extra/) are
      ignored, and an existing db_extra folder is never loaded, replaced or
      deleted.

    * A read-only default database (installed package, AppImage, macOS
      bundle) is updated into the per-user folder (%LOCALAPPDATA%\NTInfo\cdie,
      ~/.local/share/NTInfo/cdie, ~/Library/Application Support/NTInfo/cdie;
      CDIE_USER_DATA_DIR overrides), which diec and the GUIs now search first
      unless the installation is portable.

    * Added diec --checkupdate and --update, which run die-update from diec's
      folder with -D and -j passed on and return its exit code (127 when it
      cannot be started). diec still imports KERNEL32.dll only.

    * Added diec --buffersize <size> and --filebuffersize <size> (cdie only;
      Detect It Easy's diec has neither, its GUI keeps both in die.ini): the
      read buffer size (see below) and the file buffer size, below which an
      archive member is decoded in memory instead of through a temporary file
      (both 64 KiB by default, unchanged). <size> is 1K..1G (1K..64M in a
      32-bit diec), in bytes or with a K, M or G suffix in either case; a
      missing, malformed or out-of-range value is exit code 4 with nothing
      scanned, and the last one given wins. Both are set before any other
      work; die-update (--checkupdate, --update) receives neither. Every
      open file and decoder allocates a whole file buffer, so a large one
      costs that much memory even for small inputs. diec still imports
      KERNEL32.dll only.

    * The read buffer size (diec --buffersize, the GUI's Buffer size,
      Feature/ReadBufferSize; 64 KiB by default) is how much the hash,
      entropy and strings views and diec modes read at a time (strings at
      most 16 MiB), and so do the scan's MD5, SHA-1, SHA-256, CRC and
      BLAKE2sp loops and byte searches that read into a buffer of their own.
      Each buffer is no larger than what is left to read, and falls back to
      64 KiB when that much memory cannot be allocated, so the size changes
      how often the input is read, never a result.

    * Two signature databases, as in Detect It Easy: main (-D, always used)
      and custom (-C, on by default). The former extra rules are part of db,
      tagged extra (--excludetags extra skips them). diec, die-update and
      cdie_tui refuse -E/--extradatabase with exit code 4; --showdatabase and
      die-update --json report no extra database. Options > Scan has the main
      and custom folders only, the Databases combo and the directory scan's
      Options offer only Custom database, and stored
      Scan/Die/Database/Extra/* settings are neither read, written nor
      deleted. Packages no longer carry db_extra. A db_extra folder from an
      earlier build is no longer used (never loaded, updated or deleted):
      delete it or move your own .sg files to db_custom. Until Detect It Easy
      publishes the merged db, the current-database db.zip still holds those
      rules only under db_extra/, which die-update does not install.
      xxwidgets keeps its API: XXWIDGETS_SCAN_DATABASE_EXTRA is deprecated
      (setters ignore it, getters never return it, no extra control is
      created) and the default is CUSTOM; xxfclib's DB_EXTRA and
      use_extra_database are deprecated.

    * Added Update database (Ctrl+U/Cmd+U) to the Windows, GTK and macOS GUIs:
      a cancellable in-process update that reloads the databases and reports
      in the status bar. The Options > Scan update URL now defaults to the
      current-database release. Added die --smoke-update for tests.

    * xxfclib: added xx_fs_make_dir, xx_fs_rename (never replaces),
      xx_fs_remove_tree (never follows links or junctions) and
      xx_fs_current_dir. Fixed ZIP extraction to a folder, which failed every
      file member silently, and POSIX extraction of ZIP directories stored
      with modes such as 0600. xxgithub: added release URL parsing,
      xx_github_release_download_url and xx_github_release_find_asset.
      xxnetlib: XXNETLIB_XXFCLIB_TARGET selects the xxfclib archive it links.

    * The GUI keeps its Options in Detect It Easy's own store (die.ini when
      portable, else NTInfo/die; biz.ntinfo.die on macOS), shared with
      die-update and the Qt program: plain Qt value forms, only changed
      options are written and Detect It Easy's lines keep every byte. The
      language is cdie/Lang (View/Lang only becomes System or English), fonts
      always name a family Qt can resolve, #aarrggbb colors are read blended
      over white, and Detect It Easy's recent files are shown until cdie has
      its own. Settings from cdie.ini / NTInfo/cdie are copied once; both
      stores are marked cdie/Migrated. Feature/ReadBufferSize and
      Feature/FileBufferSize take effect within the Optimization page's range,
      1 KiB to 1 GiB, 1 KiB to 64 MiB in a 32-bit build, which now offers only
      those choices (0, and a value over 2147483647, which Detect It Easy
      reads as its default too, its 2 GiB and 4 GiB choices included, are the
      64 KiB default), and the stored value is kept until the size changes in
      Options; the one-time copy moves them as stored.

    * Dialogs: every dialog of the Windows, GTK and macOS GUIs is opened,
      checked and closed by the smoke tests (gui_win32, the new
      cdie.linux_dialogs, gui_cocoa). Fixed: dragging a tool dialog below its
      minimum closed it with an error; on Windows Escape/Enter on an open
      dropdown acted on the whole dialog, Enter never reached the focused
      field (Disasm Offset+Enter now acts as Go), dialogs could open larger
      than the screen, and closing About, text dialogs, Options, Strings or
      the Extractor handed the foreground to another program; a failed page
      action or a rejected font no longer closes Options and loses its
      edits; the GTK font chooser read past its title table; the signature
      editor's confirm dialogs could not open; the Extractor opens its file
      with progress and Cancel; Update database shows a failure dialog and
      translated stages; a missing main database folder keeps Options on the
      Scan page. Text dialogs (Log, "?", errors) are resizable, labels show
      '&' literally, path labels keep the file name, more strings are
      translated, and on GTK Enter on a focused button presses that button.
      On Windows the dialogs' grid follows the Controls font, so a larger
      font is no longer clipped, up to the size at which the Options dialog
      still fits the screen (beyond it text is clipped but every button stays
      reachable); windows get their size and place back when the font
      shrinks again.

    * xxfclib settings: INI saves patch only the changed lines of an existing
      file; header-less files are read and written in the QSettings dialect
      (xx_settings_set_qt_compatible); registry key lookup ignores ASCII case.

    * Packaging: die-update.exe in the Windows portable ZIP, die-update in the
      .deb, AppImage and die.app, and CDIE_INSTALL_LAYOUT=PORTABLE|FHS.
      Added tests cdie.updater (59 offline cases), cdie.gui_update and the
      library tests test_fs_tree, test_zip_unpack_path and test_github.

    * macOS: build_macos.sh builds arm64 and x64 packages (zip + pkg each,
      separate build trees; MACOS_ARCHITECTURES picks them or one universal
      pair), checks their architectures with lipo, and targets macOS 11.0
      (arm64) / 10.14 (x86_64) instead of the build machine's; die.app's
      Info.plist names that version as LSMinimumSystemVersion (a direct CMake
      build without a deployment target gets the same defaults). It needs no
      certificates or passwords: a missing, incomplete or unusable identity
      or notarization credential is skipped with a notice (ad hoc seal,
      unsigned pkg, no notarization; MACOS_ADHOC_SIGN=0 skips the seal), and
      only a Developer ID signed app or pkg is sent for notarization. CI
      builds and publishes both architectures from the Apple silicon runner
      and seals die.app in the portable ZIPs ad hoc as well.
      xxfclib picks its per-source SIMD/ARM flags from the target
      architectures (CMAKE_OSX_ARCHITECTURES), not the host, so x86_64 and
      universal builds on Apple silicon compile.

    * Added native GUI File Information for the current path (Ctrl+I on

    * Added --info/-i, --struct/-S and --showstructs/-w using native
      DataStructs for PE, ELF and thin Mach-O only, independently of signature
      databases. Added field selection, table-entry expansion and all five

    * Added public generated-fixture compatibility tests and optional strict
      diec output comparisons, with pinned-dependency CI on three platforms.
    * Exposed all-types, overlay, resource and archive-member scans in the
      console and native GUI options; TUI F2 opens the expansion controls.
      Enabled native resource streams and retained format groups in the GUI.
    * Archive member scans (--archivesscan) now match diec 4.0.0. Only ZIP,
      JAR, APK and IPA are expanded (GZIP, BZIP2, LHA and Mach-O Fat no
      longer are). Nested archives, and archive overlays and resources,
      expand down to 20 levels. Without -g only scannable members
      (executables, DEX, PDF, TAR, archives) are scanned, at most 21 per
      archive. Every member reached is CRC-checked, stored ones included: a
      damaged member is skipped and reported after the detections as
      "Last error: Invalid CRC" (a ZIP method diec does not map as "Last
      error: Unknown compression method: Unknown"), also in -j/-x/-c/-t,
      with exit code 0, instead of failing the scan. A ZIP is typed ZIP only
      when it passes XZip::isValid, and a ZIP without end records is read
      from its local headers. Members that can never be scanned are decoded
      for their CRC only, without buffering. New cdie safety limit, which
      diec does not have: at most 10,000 archive member scans per input
      (100,000 with -g), reported as "Last error: Archive member scan limit
      reached (10000)". The GUI option is now "Scan archive members".
    * Archive members larger than 256 MiB are scanned again, as diec 4.0.0
      scans them (cdie had skipped compressed ones without a message): there
      is no member size limit. A member smaller than the file buffer size is
      decoded in memory, a larger one through a temporary file. A member that
      cannot get its temporary file, whose size does not fit in the temporary
      folder (or, from 16 MiB on, where diec also uses temporary files, would
      leave less than 1 GiB free there), or whose temporary file cannot be
      written or read back is skipped without a message; a full disk no
      longer fails the whole input (a nearly full one also skips compressed
      members from 64 KiB on that do not fit, which diec scans from memory
      below 16 MiB). Zstandard
      members and XZ Blocks behind a branch (BCJ) or Delta filter are now
      decoded as they stream: zstd members had been held whole in memory,
      filtered XZ Blocks over 64 MiB skipped. The Extractor lists and
      extracts members of any size too, reads stored members in place, and
      leaves out a member that cannot get its temporary file or room for it
      instead of stopping; a damaged member still stops the listing.
    * MS-DOS files are mapped at 0x10000000, as Formats' XMSDOS and DIE 3.10
      map them: getAddressOfEntryPoint is 0x10000000 + CS:IP, and the
      native entry offset and compareEP resolve into the image. A four-byte
      '#' pointer in an MS-DOS signature is followed as a real-mode far
      pointer, as XBinary does; Borland Pascal and other DOS compiler rules
      use one. The same mapping was restored in the Qt source
      (XMSDOS::getModuleAddress returned 0, so its diec detected 2 of 34 DOS
      packer samples; now 29, as DIE 3.10 and cdie).

    * Added a Defaults button to the GUI optimization dialog. It restores both

    * PE / PE+ parser: sections, imports with position hashes, exports,

    * .NET metadata: the #Strings, #US, #Blob and #GUID heaps plus the full

    * JPEG parser: segments, JFIF version, COM comment, DQT hash, APP marker

    * Plain text detection: isPlainText() implements XBinary::isPlainTextType

    * APK parser: locates AndroidManifest.xml in the ZIP central directory,

    * PDF parser: reduces objects to token lists via classic xref tables,
      cross-reference-stream deep scan and incremental-update chaining, then
      answers getStringValuesByKey, the /Filter list, the version and the
      header comment. Stream contents are not decompressed.
    * DOTNET / FT_CLI_ASSEMBLY: a .NET PE (non-empty COM descriptor data
      directory) is additionally typed as CLI assembly. Scripts under
      db/PE/DOTNET load as that type and run only for .NET PEs, bound to a
      DOTNET object that exposes getNetVersion, getNetModuleName/AssemblyName,

    * ELF parser: header, section table (names via .shstrtab), program

    * Mach-O parser: load-command walk for LC_LOAD_DYLIB libraries, sections
      and the LC_MAIN entry point.
    * DEX parser: version, the map-items CRC-32 hash (the format detail), and
      the string / type-descriptor tables behind the obfuscator detections
      (e.g. ProGuard).
    * --verbose "Operation system" line for DEX, Mach-O, NE and ELF (previously
      only PE): DEX maps the version to an Android release ("Android(9.0)
      [Dalvik, 32-bit]"); Mach-O resolves the OS and version from the CPU type
      and the LC_BUILD_VERSION / LC_VERSION_MIN commands with the
      Foundation-version fallback ("macOS(13.0.0)[X86_64, 64-bit]", "Mac OS
      [I860_LITTLE, 32-bit]"); NE reads the target-OS byte ("Windows[286,
      16SEG]"); ELF resolves the OSABI, the program interpreter, the
      .comment-section distribution (Ubuntu/Debian/Red Hat/SUSE/...) with the
      Ubuntu release, the GNU note's "ABI: x.y.z" and the e_machine arch
      ("Ubuntu Linux(22.04.3, ABI: 3.2.0)[AMD64, 64-bit]", "Unix[MIPS,
      32-bit]"). All four match diec byte for byte.
    * --verbose "Virtual machine" line for JAR: XJAR::getFileFormatInfo reads the
      first *.class member (the one whose decompressed head carries the
      0xCAFEBABE magic), maps its major/minor version to the Java release via

    * PYC parser: the two-byte magic maps to the interpreter release
      (getFileFormatVersion, so "Python Bytecode(3.13b1)"), and detection now
      requires size >= 12, the "\r\n" marker and a magic that is a *known*

      constants tuple and reports a top-level string constant; like
      XPYC::getCodeObject it stops at the first nested code object, so it sees
      exactly the constants diec can (backing db/PYC/packer_UPP). The marshal

      overflow the stack.
    * ISO 9660: getApplicationIdentifier and getDataPreparerIdentifier read the
      Primary Volume Descriptor (offset 0x8000) fields, Latin-1 up to the first
      NUL then trimmed, so the tool/library detections (CDIMAGE, genisoimage,

    * Archive predicates over ZIP-family containers (ZIP/JAR/APK/NPM/IPA): the
      central directory is walked into a record-name list, backing
      isArchiveRecordPresent (exact) and isArchiveRecordPresentExp (regex over

    * Util object: the 64-bit arithmetic helpers div64, divu64, shlu64 and
      shru64 (Util_script), which the database uses because JS numbers are

    * New MSDOS/read builtins the database calls: isNE/isLE/isLX (the new-exe

    * Windows file and directory I/O uses the wide APIs (CreateFileW,

    * DIE signature engine: full signature syntax ('text', .., **, %%, %&,

    * Loads the stock DIE database unchanged, including the main and custom

    * Output formats: text, JSON, XML, CSV, TSV, all byte-identical to diec.
      The structured formats reproduce DiE's shapes exactly: the JSON nests
      the records under a file-part entry with QJsonObject's alphabetical key

      console/library build scripts skip src/gui by path so its WinMain never
      leaks into cdie.exe or the libraries.
    * Windows portable packaging: packaging/windows/build_portable_windows.cmd
      builds, installs and zips via CPack. The package bundles the signature
      database and the library artifacts, so the extracted folder runs with no
      arguments and can be linked against.
    * Direct, CMake-free build scripts in run/, each producing the console
      scanner AND the die_library artifacts. build_msvc.cmd emits the CRT-free
      KERNEL32-only cdie.exe plus die.dll + die.lib (shared) and die_static.lib
      (static), straight from cl (it loads vcvars itself). build_tcc.cmd /
      build_tcc.sh compile the whole scanner and library with the Tiny C
      Compiler (cdie.exe, die.dll + die.def / libdie.so, and libdie.a). Both
      glob the ~33 sources under src/, so no file list is maintained by hand.
      Two portability guards keep the TinyCC build working: the square-root path
      avoids __builtin_sqrt (TinyCC may define __GNUC__ without it) and uses the
      software Newton fallback; utils.c declares the code-page conversions that
      TinyCC's <windows.h> omits; and die.h exports through __attribute__ rather
      than __declspec under TinyCC. None of this affects the MSVC or GCC builds.
    * All C standard library calls go through x_ prefixed stubs in
      core/utils.h. core/utils.c, utils_fp.c, utils_math.c and utils_entry.c
      are the only translation units that see a platform header; FILE * never
      escapes utils.c. Macros that must expand in the caller's frame are
      exposed as X_VA_* and X_OFFSETOF.
    * Windows runtime layer is Win32 only: x_strlen is lstrlenA, x_malloc is
      HeapAlloc, x_fopen is CreateFileW, x_printf is WriteFile. lstrcmpA is
      deliberately not used - it is locale aware and would reorder the
      signature database.
    * CRT-free link on 64 bit MSVC (option CDIE_NO_CRT, default ON):
      /NODEFAULTLIB with entry point x_entry_point, which builds argv from
      GetCommandLineW and calls x_main. The resulting executable imports only
      KERNEL32.dll.
    * Own floating point conversions in core/utils_fp.c, exact via a small
      bignum: correctly rounded x_strtod (normals and subnormals), shortest
      round-trip x_dtoa_shortest (Steele & White) and the counted-digit
      x_dtoa_fixed / x_dtoa_precision. The last two follow the ECMAScript
      toFixed and toPrecision algorithms rather than printf %f / %g, which
      differ in trailing zeros, the exponential threshold and exponent
      padding. x_snprintf is integer only by design.
    * Own libm subset in core/utils_math.c (sqrt via SSE2 on x64, log, exp,
      sin and cos from the fdlibm polynomials), accurate to about 1 ULP.
    * tests/test_runtime.c covers the runtime layer directly: formatting,
      both directions of the double <-> text conversions, the math subset and
      the string and memory stubs. Configure with -DCDIE_BUILD_TESTS=ON; the
      executable exits with the number of failures. It links only
      core/utils*.c with the scanner's flags, so building it also checks that
      the CRT-free link still works.
    * Builds as strict ISO C99 on both MSVC 19.44 and GCC 11.4 with no
      warnings, and the two produce identical scan output.
    * Verified byte-identical to diec on a 348 file corpus (Windows system
      DLLs, Visual Studio .NET assemblies, Qt binaries, Python, plus a whole
      directory of scripts, text, images, an APK and a PDF): 348 same,
      0 different. A separate 40 file PDF sweep (classic xref, cross-reference
      streams, incremental updates) also matches, as does the APK manifest
      extraction. A 30 file subset is compared across every output mode
      (-j -x -c -t -p -b), 30/30 in each, and --showdatabase matches too,
      counts and names.
